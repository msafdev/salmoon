# Getting Started & Setup Guide

This guide walks you through setting up, configuring, and running the **Salmoon** (`msafdev`) codebase locally.

---

## 📋 Prerequisites

Ensure you have the following installed on your machine:

- **[Bun](https://bun.sh/)** (version 1.0+ recommended) or **Node.js** (v20.x or higher)
- **Git**
- A **[Supabase](https://supabase.com/)** project (for Auth, Guestbook, and Notes)
- A **[Google Cloud](https://console.cloud.google.com/)** Service Account with Google Calendar API enabled (optional for calendar bookings)

---

## 🛠️ Installation

1. **Clone the repository:**

   ```bash
   git clone https://github.com/msafdev/salmoon.git
   cd salmoon
   ```

2. **Install dependencies:**

   ```bash
   bun install
   # Or if using npm/pnpm:
   # npm install
   ```

3. **Create local environment file:**
   ```bash
   cp .env.example .env.local
   ```

## 🗄️ Supabase Database Setup & Schema

Run the following SQL in your **Supabase SQL Editor** to initialize the required tables, types, foreign keys, and Row Level Security (RLS) policies:

```sql
-- 1. Create color enum for Note canvas
CREATE TYPE color AS ENUM (
  'red', 'pink', 'blue', 'sky', 'green', 'emerald', 'purple', 'yellow', 'orange'
);

-- 2. Create User Profiles table
CREATE TABLE public.profile (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  name TEXT,
  avatar_url TEXT
);

-- 3. Create Guestbook table with support for threaded replies
CREATE TABLE public.guestbook (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  content TEXT NOT NULL,
  user_id UUID REFERENCES public.profile(id) ON DELETE CASCADE,
  parent_id BIGINT REFERENCES public.guestbook(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
);

-- 4. Create Note table for Infinite Canvas Sticky Notes
CREATE TABLE public.note (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  content TEXT NOT NULL,
  color color DEFAULT 'yellow'::color NOT NULL,
  user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL
);

-- 5. Enable Row Level Security (RLS)
ALTER TABLE public.profile ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.guestbook ENABLE ROW LEVEL SECURITY;
ALTER TABLE public.note ENABLE ROW LEVEL SECURITY;

-- 6. Profile RLS Policies
CREATE POLICY "Public profiles are viewable by everyone."
  ON public.profile FOR SELECT USING (true);

CREATE POLICY "Users can insert their own profile."
  ON public.profile FOR INSERT WITH CHECK (auth.uid() = id);

CREATE POLICY "Users can update own profile."
  ON public.profile FOR UPDATE USING (auth.uid() = id);

-- 7. Guestbook RLS Policies
CREATE POLICY "Guestbook entries are viewable by everyone."
  ON public.guestbook FOR SELECT USING (true);

CREATE POLICY "Authenticated users can create guestbook entries."
  ON public.guestbook FOR INSERT WITH CHECK (auth.role() = 'authenticated' AND auth.uid() = user_id);

CREATE POLICY "Users can delete their own guestbook entries."
  ON public.guestbook FOR DELETE USING (auth.uid() = user_id);

-- 8. Note RLS Policies
CREATE POLICY "Notes are viewable by everyone."
  ON public.note FOR SELECT USING (true);

CREATE POLICY "Authenticated users can create notes."
  ON public.note FOR INSERT WITH CHECK (auth.role() = 'authenticated' AND auth.uid() = user_id);

-- 9. Automatic Profile Creation Trigger on OAuth Sign-in
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO public.profile (id, name, avatar_url)
  VALUES (
    new.id,
    COALESCE(new.raw_user_meta_data->>'full_name', new.raw_user_meta_data->>'name', 'Anonymous'),
    new.raw_user_meta_data->>'avatar_url'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();
```

## 🏃 Running the Application

| Script               | Command                | Purpose                                                               |
| :------------------- | :--------------------- | :-------------------------------------------------------------------- |
| **Development**      | `bun run dev`          | Runs **Velite** in watch mode and **Next.js** dev server concurrently |
| **Build Content**    | `bun run velite:build` | Compiles MDX collections into `.velite` data                          |
| **Production Build** | `bun run build`        | Compiles Velite content and runs `next build`                         |
| **Production Start** | `bun run start`        | Boots production server on `localhost:3000`                           |
| **Linting**          | `bun run lint`         | Checks ESLint rules across the project                                |
| **Formatting**       | `bun run format`       | Formats all files using Prettier and Tailwind plugin                  |

### Start Development Server

```bash
bun run dev
```

Open [http://localhost:3000](http://localhost:3000) in your browser.

## 🌐 OAuth Provider Setup (Supabase)

To enable GitHub and Google login on `/guestbook` and `/note`:

1. Navigate to **Supabase Dashboard** > **Authentication** > **Providers**.
2. **GitHub**:
   - Create a GitHub OAuth App at [GitHub Developer Settings](https://github.com/settings/developers).
   - Set Authorization callback URL to: `https://<YOUR_SUPABASE_PROJECT>.supabase.co/auth/v1/callback`.
   - Copy Client ID and Client Secret into Supabase.
3. **Google**:
   - Create OAuth credentials in [Google Cloud Console](https://console.cloud.google.com/apis/credentials).
   - Set Authorized Redirect URI to: `https://<YOUR_SUPABASE_PROJECT>.supabase.co/auth/v1/callback`.
   - Copy Client ID and Client Secret into Supabase.
